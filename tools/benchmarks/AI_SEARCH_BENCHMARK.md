# AI 检索 benchmark v3

目的：既验证有证据的问题能答出内容，也验证无足够证据的问题不会被编造答案。此集用于本地开发回归，不是人工标注 gold，不用于估计真实流量上的准确率。

固定清单：[`ai_search_cases.json`](ai_search_cases.json)。共 18 个 query：10 个有答案、8 个无足够证据，覆盖 10 个主题领域、17 种需求意图。第一个用例固定为“图书馆开放时间”。本地库最新帖子为 2026-08-12，不能替代当前实时信息或官方公告。

| 类型 | 用例 | 检查重点 |
|---|---|---|
| 历史时间与短回复 | 001、002 | 开门、闭馆与实际离开分清；“7：00”继承真实帖子上下文 |
| 借阅流程 | 003 | 密排库各库规则、押证和馆内阅读，不能漏掉关键限制 |
| 购物地点 | 004 | 接受已核对的不同有效来源，不只认某一条帖号 |
| 带日期的安排 | 005 | 只陈述指定历史时期，不变成今日通用安排 |
| 特定机构无回复 | 006 | 法学院图书馆不能用总图书馆时间代答 |
| 当前/官方信息缺失 | 007、016 | 历史经验不能代替 2026 年 11 月官方信息 |
| 空时间窗口 | 008 | 明确时间过滤后无资料，不能退回旧年份凑答案 |
| 不存在实体、精确标识 | 009、010 | 保留实体与标识，不降格为泛泛主题检索后猜答案 |
| 校园卡办事地点 | 011 | 综合服务中心、自助机等地点线索；不编造费用和步骤 |
| 费用和更正 | 012 | 保留“20”被更正为“10r、两小时”等上下文 |

| 历史技术故障 | 014 | 只回答当时其他人的观察，不诊断当前个人电脑 |

## 固定预期和证据

每条清单都有自然语言参考答案或拒答理由。正例提供经源记录核对的可接受帖子 ID 集合和必要答案要点；ID 仅用于评估，生产检索不会读取清单。实际原文与评论快照写入 Git-ignored 的 `reports/generated/ai-search/design-review.json`，不提交真实论坛数据库、用户身份或完整原文。

参考答案是对历史用户陈述的忠实整理，不把用户陈述当成当前官方事实。不同来源可有更正或冲突，保留准确归属和时间即可；不能为了消除冲突而编造统一答案。开放式问题允许多条有效来源；已列参考 ID 仅作召回诊断，不把其他有效来源的正确回答判错。仍要求答案要点、实际来源范围匹配、精确原文引用及源记录复核；005、014 两条限定历史事件仍强制引用对应记录。修订须显式版本变更、重新离线核对，旧结果保留。

## 验收门槛

1. 正例：必须产生事实回答，每条有可追溯原文引用，包含必要答案要点，来源符合原问题范围；限定历史事件还需引用指定记录。参考帖命中另行记录为召回诊断。仅检索到相关帖不算答出。
2. 负例：必须是 `no_answer` 或 `no_results`，且事实回答为空。API 报错、未配置、`unverified` 拦截不算成功拒答；拦截另记安全结果。
3. 引用：每条显示说法必须能追到实际正文/评论的精确片段和真正所属帖子，数字编号由服务器生成。原文存在不等于语义被支持，另做逐项模型辅助检查及人工源记录抽查；模型复核不充当 gold。
4. 保留所有失败轮、查询改写、候选 ID、阶段响应、拒绝计数、用量和时间。不能用重试后的成功覆盖首次失败。
5. 自动检查结果是有限回归门槛，不是完整语义评测。答案要点的正则检查和参考 ID 不充分证明回答准确；应直接查看保存的答案、引用原文和冲突处理。

## 顺序与命令

先检查设计及源记录，不调用 AI：

```powershell
python -B -m tools.benchmarks.benchmark_ai_search --validate-only
python -B -m pytest tests/test_ai_search.py tests/test_ai_search_quality.py -q
```

本地核对通过后，保存的清单 hash 与源数据库修改时间成为运行前提。清单或数据库改变时，须重新做设计核查。运行真实 API 必须显式指定 `--live`：

```powershell
python -B -u -m tools.benchmarks.benchmark_ai_search --live --label frozen-v3 --repeats 2 --concurrency 18
```

只复核部分失败用例：

```powershell
python -B -u -m tools.benchmarks.benchmark_ai_search --live --cases 003,018 --label targeted-check
```

每轮输出独立目录中的 `results.json` 和 `answers.md`，包含每个 query 的参考答案、实际回答、来源和失败条件。只读本地论坛库、使用已配置 AI；不触发小程序爬虫，不改 cookie、队列或配额，不自动重试。每条 query 最多 4 次 AI 请求、8 路本地检索；无候选、无充分证据或校验失败时提前停止。

CLI 默认 `--concurrency 18`，接受 1–18；同时记录逐条耗时与整轮墙钟，不能把两者混淆。普通 pytest 不调用真实 AI。

## Admin 中查看和重测

本地入口：<http://127.0.0.1:8099/admin/ai-search/bench>。页面只读展示历史目录中的原始轮次，并提供全量、失败项和单条真实 API 重测。新轮次保存在 `data/ai-search-bench/`（实际位置跟随 AI 配置目录），同一请求幂等且一次只跑一轮；18 条 query 共用生产服务的 18 个名额。先完成本地源记录核查，再启动模型调用；刷新页面不会重跑，服务重启后未完成轮只显示中断。

Admin 与 CLI 共享 `app/services/ai_search_benchmark_spec.py` 中的门槛，清单仍以本目录 JSON 为准。参考答案只用于判分，不传入检索/生成流程。失败记录不会被重测结果覆盖。

页面显示运行前的费用/时间区间，完成后显示已返回 token 的费用折算、真实墙钟、查询累计耗时。只对已核对的 DeepSeek 官方地址/模型套用价目表，区间覆盖空闲和高峰；用量缺失、异常中断或自定义代理会明确标记未知。真实网络错误不算正确拒答，也不自动重试。详见 [功能文档](../../docs/features/admin-ai-search.md)。

## 设计期间已发现的问题

设计核查保留了 `before`、`before-diverse`、`first-fix`、`after-v2` 的本地原始结果。早期清单只列单个参考帖子，使买花、夜间打印的其他有效来源被误判为失败；v2 在冻结前逐条补充核对过的合法来源。早期负例检查也把校验拦截当作拒答成功，v2 明确区分正确拒答、拦截未支持答案和运行失败。原始结果不删除，可按冻结规则重评，不能直接混用不同标准的分数。

v3 设计修订：重复测试证明校园卡等开放式问题存在多条同等有效来源，少量参考 ID 不能穷尽答案。因此将这些 ID 的命中改为诊断指标，保留硬性答案要点、来源范围、精确引用及源记录复核；历史事件仍要求对应记录。本修订在后续真实调用前重新离线核查，v2 原始结果保留，不能混用分数。规划接口失败也不能被改标为无结果；同一 worker 复用连接，不自动重试。
